# 4장에서 클로드코드에 입력한 것

> 사람이 친 지시를 순서대로, 원문 그대로.

## P4-1

```
같은 날 두 번 실행하면 같은 공시가 또 와. 한 번 보낸 공시는 다시 보내지 않게 해 줘. 만들고 실제로 두 번 실행해서 두 번째에는 안 가는 것까지 확인해 줘.
```

왜 이렇게 썼나 — 2장에서 미룬 중복 처리. 방법은 맡기고 검증 방법(두 번 실행)만 지정한다

## P4-2

```
확인하지 않았다고 한 세 가지를 실제로 시험해 줘. 텔레그램으로 실제로 보내지 않아도 되는 건 가짜로 해도 되는데, 무엇을 진짜로 하고 무엇을 가짜로 했는지 구분해서 알려 줘.
```

왜 이렇게 썼나 — 세션이 밝힌 빈칸을 채운다. 시험에서 나오는 결함은 지어낸 것이 아니다

## P4-4

```
sent.json 에서 한 건을 지우고 터미널에서 node notify.js 20261001 을 동시에 두 번 돌려 봤더니 같은 공시가 텔레그램으로 두 번 왔어. 두 실행 모두 새로 보낼 것 1건, 메시지 1개로 보냄이라고 나왔고 sent.json 은 5건으로 멀쩡해. 원인을 찾아서 고쳐 주고, 이번 일을 다음 세션이 같은 실수를 하지 않게 위키에 교훈으로 남겨 줘.
```

왜 이렇게 썼나 — 실제로 난 일을 사실대로 전한다(일부러 동시에 돌렸다는 것까지). 교훈의 형식은 맡긴다
