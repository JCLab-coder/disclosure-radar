# 9장에서 클로드코드에 입력한 것

> 사람이 친 지시를 순서대로, 원문 그대로.

## P9-1

```
이 저장소의 위키 방식(규칙 파일, 위키 뼈대, 점검 스크립트와 훅, 점검 절차)을 다른 프로젝트에도 그대로 쓸 수 있게 starter 폴더로 뽑아 줘. 이 프로젝트에만 해당하는 내용은 빼고, 다른 프로젝트에 넣는 순서도 같이 적어 줘. 커밋해 줘.
```

왜 이렇게 썼나 — 다른 프로젝트로 옮길 뼈대. 무엇이 고유 내용인지는 세션이 고른다

## P9-2

```
../disclosure-radar/starter 의 위키 방식을 이 프로젝트에 넣어 줘. starter/README.md 순서대로 하되, 이 프로젝트의 CLAUDE.md 에 적힌 결정과 docs/ 의 내용은 위키로 옮겨. 옮기면서 빠지거나 바뀌는 내용이 없어야 해. 손대기 전에 계획부터 보여 줘.
```

왜 이렇게 썼나 — 이미 규칙과 문서가 있는 프로젝트. 코덱스로. 계획부터

## P9-3

```
계획대로 진행해. 다만 규칙 9와 부딪히는 트럼프는 네가 예외로 정하지 말고 나한테 먼저 물었어야 해. 트럼프는 뉴스 검색 키워드 예시라서 그대로 두기로 할게(사용자 결정). 위키에 그렇게 적어 줘.
```

왜 이렇게 썼나 — 스스로 정한 예외를 짚고, 사람이 정한다. 그리고 진행시킨다

## P9-4

```
응, 그 예시는 자리표시자로 바꾸고, 원문에서 바꾼 유일한 곳이라고 기록해 줘(사용자 결정). 그다음 계획대로 끝까지 진행해.
```

왜 이렇게 썼나 — 원문 보존과 비밀값 점검이 부딪힌 곳. 사람이 정하고 기록하게 한다

## P9-5

```
이 프로젝트는 방금 코덱스가 CLAUDE.md 와 docs/ 의 내용을 위키로 옮겼어. 옮기기 전 커밋 0597f5b 의 CLAUDE.md 와 docs/ 를 지금 위키와 대조해서, 빠지거나 바뀐 내용이 있는지 봐 줘. 코덱스가 만든 검증 스크립트 말고 네 방법으로 확인해. 고치지는 마.
```

왜 이렇게 썼나 — 다른 도구가 한 일을 다른 도구가, 다른 방법으로 대조한다. 284/284 라는 말을 믿지 않고 확인

## P9-6

```
1번은 놓치면 바로 문제가 생기는 주의만 CLAUDE.md 에 한 줄씩 남기고, 자세한 건 위키 페이지를 가리키게 해 줘. 2번은 나도 구체적인 규칙까지 내가 정했는지 기억이 안 나. 확인 안 됨으로 고쳐 줘. 3, 4, 5번은 네가 고쳐도 돼. 커밋해 줘.
```

왜 이렇게 썼나 — 자동으로 읽히는 자리와 찾아 읽는 자리를 나눈다. 기억 안 나는 것은 확인 안 됨
