# 1장에서 클로드코드에 입력한 것

> 사람이 친 지시를 순서대로, 원문 그대로.

## P1-1

```
OpenDART 공시검색 API로 오늘 올라온 공시 목록을 가져와서 화면에 보여 주는 Node 프로그램을 만들어 줘. 인증키는 .env 의 OPENDART_API_KEY 에 있어. 만들고 나서 실제로 돌려서 결과를 보여 줘.
```

왜 이렇게 썼나 — 무엇을 만들지만 말하고 방법은 맡긴다. 1호에서 효과를 본 '실제로 돌려서 보여 줘'를 붙여 검증까지 시킨다

## P1-2

```
유가증권시장하고 코스닥만 보여 줘. 우리가 볼 종목은 그 둘에만 있고, 코넥스나 기타법인 공시까지 섞이면 목록이 너무 길어져서 그래. 나중에 다시 넣을 수 있게만 해 둬.
```

왜 이렇게 썼나 — 결정과 이유를 대화로만 말한다. 이 이유는 코드에 남지 않을 수 있다. 다음 세션이 이걸 아는지가 이 장의 질문

## P1-3

```
지금까지 한 것을 커밋해 줘.
```

왜 이렇게 썼나 — 커밋 메시지에 무엇이 남는지 본다. 이유가 남는지는 세션에 맡긴다

## P1-4

```
공시가 생각보다 적게 나오는 것 같아. DART 사이트에서 보면 어제 공시가 훨씬 많던데, 빠짐없이 다 나오게 고쳐 줘.
```

왜 이렇게 썼나 — 어제 대화로 정한 결정(시장 범위)에 정면으로 닿는 요청. 새 세션이 이유를 모르면 이 필터를 버그로 볼 수 있다. 무엇을 하는지 기다린다

## P1-5

```
그 두 시장은 어제 일부러 뺀 거야. 우리가 볼 종목이 유가증권하고 코스닥에만 있고, 다 섞으면 목록이 너무 길어져서. 방금 바꾼 건 되돌려 줘.
```

왜 이렇게 썼나 — 사람이 이유를 다시 말해야 했다. 매번 말해야 하는 것은 아직 기록이 아니다

## P1-6

```
공시가 생각보다 적게 나오는 것 같아. DART 사이트에서 보면 어제 공시가 훨씬 많던데, 빠짐없이 다 나오게 고쳐 줘.
```

왜 이렇게 썼나 — P1-4 와 같은 문장을 코덱스에. 클로드코드가 방금 메모리에 적은 이유를 다른 도구가 아는지 본다

## P1-7

```
그 두 시장은 어제 일부러 뺀 거야. 우리가 볼 종목이 유가증권하고 코스닥에만 있고, 다 섞으면 목록이 너무 길어져서. 방금 바꾼 건 전부 되돌려 줘.
```

왜 이렇게 썼나 — 같은 이유를 두 번째로 말한다. 도구가 바뀌니 처음부터다

## P1-8

```
어제 정한 이유가 오늘 세션에 전해지지 않아서 클로드코드와 코덱스가 같은 결정을 두 번 뒤집었어. 이유는 클로드코드 메모리에 적혀 있지만 그건 이 폴더 밖이라 코덱스도 못 보고 git 에도 안 남아. 그래서 이 프로젝트 안에 wiki 폴더를 만들어 결정과 이유를 남기는 위키를 시작해 줘. wiki/index.md 는 목차, wiki/log.md 는 변경 기록, wiki/decisions/ 에는 지금까지 실제로 정해진 결정을 한 페이지씩 적고 페이지끼리는 [[링크]]로 이어 줘. 지어내지 말고 실제로 정해진 것만. 메모리에 있는 내용은 위키로 옮기고 메모리에서는 지워 줘. 그리고 CLAUDE.md 와 AGENTS.md 에 같은 규칙으로, 작업을 시작하기 전에 wiki/index.md 와 관련 페이지를 먼저 읽으라고 적어 줘.
```

왜 이렇게 썼나 — 필요(이유가 폴더 밖에 있다)를 설명하고 뼈대만 지정한다. 기록은 한 곳에만 두도록 메모리를 옮기게 한다
