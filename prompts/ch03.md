# 3장에서 클로드코드에 입력한 것

> 사람이 친 지시를 순서대로, 원문 그대로.

## P3-1

```
관심 종목 공시마다 내용을 AI로 세 줄 요약해서 텔레그램 메시지에 같이 넣어 줘. AI 는 .env 의 OPENROUTER_API_KEY 로 OpenRouter 를 쓰면 돼. 비용이 많이 나오지 않게 해 주고, 만들고 실제로 한 번 보내서 확인해 줘.
```

왜 이렇게 썼나 — 무엇을, 어떤 키로, 어떤 조건(비용)으로만 말한다. 요약에 필요한 자료(원문 API, 모델, 요금)는 일부러 주지 않는다

## P3-2

```
요약 5건을 모두 원문과 대조했다고 했는데, 실제로 어떤 명령으로 몇 건의 원문을 요약과 맞춰 봤는지 이 대화에 남은 것만으로 정확히 말해 줘.
```

왜 이렇게 썼나 — 1호 4장 방식: 결론 대신 근거를 묻는다. 답을 주지 않고 셈을 시킨다

## P3-3

```
고마워. 이번 일로 규칙을 만들자. 첫째, 위키의 확인 칸에는 실제로 돌린 명령과 범위(몇 건 중 몇 건, 무엇과 무엇을 비교했는지)만 적고 확인하지 않은 것은 확인하지 않았다고 적어. 둘째, 이번에 알아낸 자료(OpenDART 공시 원문 API 형식, OpenRouter 모델과 요금)는 결정이 아니니까 wiki/references/ 에 따로 페이지로 만들고 출처 주소와 확인한 날짜를 적어. 셋째, 위키에 있는 것을 물으면 근거 페이지를 달아서 답하고, 위키에 없는 것은 없다고 말해. 이 셋을 CLAUDE.md 와 AGENTS.md 에 넣어 줘. 그리고 나머지 2건도 원문을 출력해서 요약과 맞춰 본 뒤 그 결과를 규칙대로 적어 줘. 다 되면 커밋해 줘.
```

왜 이렇게 썼나 — 사고에서 규칙 셋: 확인 칸 형식, 자료 페이지(references), 위키에 묻기. 남은 확인도 끝낸다

## P3-4

```
요약은 어떤 모델로 하고, 한 건에 비용이 대략 얼마나 들어? 코드는 고치지 말고 답만 해 줘.
```

왜 이렇게 썼나 — 위키에 있는 자료를 묻는다. 근거 페이지를 다는지

## P3-5

```
OpenDART 공시 원문 API는 하루에 몇 번까지 부를 수 있어? 이것도 답만 해 줘.
```

왜 이렇게 썼나 — 위키에 없는 자료. 없다고 말하는지, 지어내는지

## P3-6

```
응, OpenDART 공식 안내에서 확인해서 출처 주소와 날짜를 붙여 적어 줘. 다 되면 커밋해 줘.
```

왜 이렇게 썼나 — 자료 넣기: 공식 출처를 찾아 날짜와 함께 위키에

## P3-7

```
위키를 보다가 발견했는데, disclosure-summary.md 확인 칸에 공시에 나온 임원들 실명이 적혀 있어. 공시 자체는 공개된 거지만 이 저장소는 나중에 공개할 거라서 위키에 개인 이름은 남기고 싶지 않아. 이름은 접수번호로만 가리키게 고치고, 위키에 개인 이름이나 연락처를 적지 않는다는 규칙을 CLAUDE.md 와 AGENTS.md 에 넣어 줘. 다 되면 커밋해 줘.
```

왜 이렇게 썼나 — 사람이 위키를 읽다 발견한 문제. 저장소 공개를 전제로 위키에 남길 것과 안 남길 것을 정한다
