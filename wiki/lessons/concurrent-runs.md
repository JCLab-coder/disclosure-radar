# 차례로 두 번 돌려 본 것은 동시에 두 번 돌린 것을 확인한 게 아니다

- 겪은 날: 2026-10-03
- 관련: [[index]], [[log]], [[sent-dedup]]

## 무슨 일이 있었나

[[sent-dedup]] 을 만들 때 `node notify.js 20261001` 을 **차례로** 두 번 돌려 두 번째가 0건인 것을 보고, 결정 페이지에 "같은 날 여러 번 실행해도 새 공시만 간다"고 적었다. 동시에 돌리는 경우는 시험하지 않았고, "확인하지 않았다"고 적지도 않았다.

사용자가 `sent.json` 에서 한 건을 지우고 터미널에서 같은 명령을 **동시에** 두 번 돌리자, 같은 공시가 텔레그램으로 두 번 왔다. 두 실행 모두 "새로 보낼 것 1건", "메시지 1개로 보냄"이라고 나왔고 `sent.json` 은 5건으로 정상이었다.

## 원인

`notify.js` 는 `sent.json` 읽기 → 새 공시 고르기 → 요약·전송 → `sent.json` 쓰기를 차례로 한다. 이 구간을 통째로 막는 장치가 없었다. 두 실행이 둘 다 상대가 쓰기 전에 `sent.json`(4건)을 읽었으므로, 둘 다 같은 1건을 "새것"으로 보고 보냈다. 쓰기는 둘 다 같은 5건을 썼기 때문에 `sent.json` 만 보면 멀쩡해 보인다. 그래서 파일만 봐서는 중복 전송을 알 수 없다.

## 교훈

- 상태 파일을 읽고, 판단하고, 무언가를 하고, 다시 쓰는 코드(중복 방지·카운터·"이미 했나" 확인)는 **동시에 둘이 돌 때**를 따로 생각한다. 읽기부터 마지막 쓰기까지를 잠금 하나로 감싸야 한다. 파일 쓰기 하나만 원자적으로 만드는 것으로는 막히지 않는다.
- "여러 번 실행해도"라고 적을 때는 차례로 실행했는지 동시에 실행했는지 구분해서 적는다. 차례로만 해 봤으면 동시 실행은 "확인하지 않았다"고 적는다.
- 결과를 볼 때 상태 파일만 보지 말고 실제로 밖으로 나간 것(전송 횟수)을 센다. 이번에는 `sent.json` 은 정상이었고 전송만 두 번이었다.
- 고치기 전에 고치기 전 코드로 같은 문제를 먼저 재현하고, 같은 시험으로 고친 뒤를 확인한다. 동시성 문제는 한 번 통과로 끝내지 말고 여러 번 돌린다.
- 실제 외부로 보내지 않고도 재현할 수 있다. scratchpad 에 `notify.js` 를 복사하고, 가짜 `dart.js`(조회를 일부러 늦춤)와 가짜 `node-telegram-bot-api`(보내지 않고 전송 기록만 남김)를 두면 된다. 이번 시험 방법은 [[sent-dedup]] 확인 칸에 있다.
