# OpenDART 공시서류원본 API (document.xml)

- 종류: 자료 (결정이 아님)
- 출처:
  - `https://opendart.fss.or.kr/api/document.xml?crtfc_key=<키>&rcept_no=<접수번호>` 를 직접 호출한 응답 (응답 형식)
  - OpenDART FAQ "오픈API 이용한도는 어떻게 되나요?" (2020-01-18 게시): `https://opendart.fss.or.kr/cop/bbs/selectArticleList.do?bbsId=B0000000000000000002` 목록에서 여는 글. 본문은 `https://opendart.fss.or.kr/cop/bbs/selectArticleDetail.do` 에 `nttId=29&bbsId=B0000000000000000002` 를 POST 해서 받았다. (호출 한도)
  - OpenDART 개발가이드 공시서류원본파일: `https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003` (오류 코드)
- 확인한 날: 2026-10-03 (응답 형식, 호출 한도 모두)

## 직접 확인한 것

scratchpad 의 `probe.mjs` 로 2026-10-01 관심 종목 공시 5건(`20261001900418`, `20261001900314`, `20261001000251`, `20261001000203`, `20261001800065`)을 받았다. 그 뒤 `unzip -l`, `file`, `head` 로 열어 봤다.

- 응답 헤더 `Content-Type`: `application/x-msdownload;charset=UTF-8`. 본문은 zip 이다(앞 4바이트 `504b0304`). 5건 중 5건.
- zip 크기는 1,627 ~ 5,381 바이트였다.
- zip 안에는 `<접수번호>.xml` 파일 하나만 있었다. 5건 중 5건.
- 인코딩은 5건 모두 UTF-8 이었다(`file` 명령). HTML 형식 파일은 `<meta ... charset=euc-kr>` 이라고 적혀 있지만 실제로는 UTF-8 이다.
- 파일 형식은 두 가지였다.
  - HTML(`<html>` 로 시작, `<STYLE>` 포함): 수시공시 3건(IR 2건, 공정공시 1건).
  - dart4 XML(`<?xml ...?>` 다음 `<DOCUMENT ... dart4.xsd>`): 임원ㆍ주요주주 특정증권등 소유상황보고서 2건.
- 태그와 `<style>` 을 걷어낸 글자 수(`dart.js` 의 `fetchDocumentText()`)는 404 ~ 1485자였다(4건을 잼).
- 원문에 개인 정보가 들어 있었다. 출력해 본 공시 중 에코프로비엠 2건(`20261001900314`, `20261001900418`)에 담당자 이름·전화번호가 있었다. 삼성전자 `20261001000203` 에는 보고자 생년월일(6자리)과 주소(동까지)가 있었다. 나머지 공시는 이 부분을 출력하지 않아 확인하지 않았다.

## 호출 한도 (공식 안내에서 확인한 것)

2026-10-03 에 위 FAQ 글과 개발가이드를 `curl` 로 받아 태그를 걷어내고 읽었다. 공식 안내에 적힌 내용이고, 실제로 한도까지 불러 본 것은 아니다.

- FAQ 원문 그대로:

  > Open DART 홈페이지 오픈API 서비스의 일일한도는 다음과 같습니다.
  >
  > 1. 개인 : 일 20,000건 (서비스별 한도가 아닌 오픈API 83종 전체 서비스 기준)
  > 2. 기업(사업자등록증 및 IP 등록)
  > 1) 공시검색, 기업개황 2종 : 한도 없음
  > 2) 공시검색, 기업개황을 제외한 모든서비스 81종 : 일 20,000건(서비스별 한도가 아닌 81종 서비스 전체 기준)
  >
  > \* 일일한도를 준수하더라도 서비스의 안정적인 운영을 위하여 과도한 네트워크 접속(분당 1,000회 이상)은 서비스 이용이 제한될 수 있으니 이용에 참고하시기 바랍니다.

- 정리하면 `document.xml` 만의 한도는 따로 없고, 오픈API 전체 호출을 합쳐서 하루 20,000건이다. 개인 키는 공시검색(`list.json`)도 이 20,000건에 들어간다. 기업 키는 공시검색·기업개황이 한도에서 빠진다. 분당 1,000회 이상은 제한될 수 있다.
- 한도를 넘으면 오류 코드 `020` 이 온다. 개발가이드(`document.xml`·`list.json` 두 페이지 모두 같은 문구) 원문: "요청 제한을 초과하였습니다. 일반적으로는 20,000건 이상의 요청에 대하여 이 에러 메시지가 발생되나, 요청 제한이 다르게 설정된 경우에는 이에 준하여 발생됩니다."
- FAQ 게시일은 2020-01-18 이다. 2026-10-03 에도 같은 글이 FAQ 목록에 있었다. 글이 그 뒤에 고쳐졌는지는 알 수 없다.

## 확인하지 않은 것

- 오류 응답의 형식. `fetchDocumentText()` 는 zip 이 아니면 XML 안의 `<message>` 를 읽도록 짰지만, 실제로 오류를 받아 보지는 않았다.
- 파일이 여러 개 든 zip(정기보고서 등). 받아 본 적이 없다. 코드는 `<접수번호>.xml` 을 먼저 찾고, 없으면 첫 파일을 쓴다.
- 이 프로젝트의 `.env` 의 `OPENDART_API_KEY` 가 개인 키인지 기업 키인지. 그래서 공시검색이 한도에 들어가는지는 확인하지 않았다.
- 한 번 실행(`node notify.js`)에 OpenDART 를 모두 몇 번 부르는지. `document.xml` 은 관심 종목 공시 건수만큼(2026-10-01 은 5번) 부르지만, 공시검색(`list.json`) 호출 횟수는 세지 않았다.
- 오류 코드 `020` 을 실제로 받아 본 적은 없다.
