# 하루에 보내는 메시지는 20개까지

- 정한 날: 2026-10-03
- 누가 정함: 항목마다 다르다. 각 항목 끝 괄호에 적었다. 근거는 아래 "근거" 참고.
- 상태: 유지
- 관련: [[index]], [[log]], [[watchlist-telegram]], [[sent-dedup]], [[disclosure-summary]], [[concurrent-runs]], [[railway-deploy]]

## 결정

- `notify.js` 는 하루에 보내는 텔레그램 메시지가 20개에 닿으면 그날은 더 보내지 않는다. (사용자)
- "20개를 넘으면"을 "20개까지 보내고 21번째부터 보내지 않는다"로 읽었다. 하루 최대 20개다. (AI 기본값)
- 세는 단위는 공시 건수가 아니라 `sendMessage` 로 실제 간 메시지 수다. 4096자를 넘어 나뉜 메시지는 하나하나 센다. (메시지를 센다는 것은 사용자, 나뉜 메시지를 따로 세는 것은 AI 기본값)
- "하루"는 공시 날짜(`node notify.js YYYYMMDD` 의 인자)가 아니라 보내는 날(KST, `dart.js` 의 `todayKST()`)이다. 날짜가 바뀌면 0부터 다시 센다. (AI 기본값)
- 센 값은 프로젝트 폴더의 `sent-count.json`(`{"date":"YYYYMMDD","count":N}`)에 둔다. `.gitignore` 에 넣어 커밋하지 않는다. 파일이 없거나 날짜가 오늘이 아니면 0으로 본다. (AI 기본값)
- 메시지 하나가 전송에 성공할 때마다 1을 더해 바로 기록한다. 전송에 실패한 메시지는 세지 않는다. (AI 기본값)
- `sent-count.json` 읽기·쓰기는 `sent.json` 과 같이 `sent.lock` 안에서 한다. 동시에 실행돼도 합쳐서 20개를 넘지 않게 하려는 것이다. (AI 기본값)
- 한도 때문에 못 보낸 공시는 `sent.json` 에 남기지 않는다. 그래서 다음 날 실행하면 간다. 버리지 않는다. (AI 기본값)
- 실행을 시작할 때 이미 20개면 원문 조회·요약(OpenRouter)도 하지 않고 종료 코드 0 으로 끝난다. (AI 기본값)
- 한 실행 중간에 한도에 닿으면 남은 메시지는 보내지 않고, 남은 메시지 수와 공시 건수를 출력한다. 이때 못 보낸 공시도 이미 요약은 한 상태라 그 요약 비용은 든다. (AI 기본값)
- `sent-count.json` 이 깨졌거나 형식이 맞지 않으면 보내지 않고 오류로 끝난다(종료 코드 1). [[sent-dedup]] 의 깨진 `sent.json` 처리와 같게 했다. (AI 기본값)
- 한도 20 은 `notify.js` 의 `DAILY_LIMIT` 에 있다. (AI 기본값)

- 2026-10-03 덧붙임: 서버(Railway)에서는 `sent-count.json` 을 볼륨 `/data` 에 둔다(`STATE_DIR`). 서버와 로컬은 따로 센다. [[railway-deploy]] 참고. (AI 기본값)

## 이유

- 보내는 날 기준인 이유: 지난 날짜를 여러 번 실행해도 오늘 받는 메시지 수가 20개를 넘지 않아야 하기 때문이다.
- 못 보낸 공시를 남기지 않는 이유: `sent.json` 에 넣으면 그 공시는 영영 안 간다.
- 전송 실패를 세지 않는 이유: 받는 사람에게 가지 않은 메시지다.

## 확인

- 2026-10-03 가짜로 실행: scratchpad 폴더에 `notify.js` 를 복사하고(`cmp` 로 원본과 같음 확인), 가짜 `dart.js`(날짜마다 삼성전자 공시 `FAKE_N` 건, 오늘 날짜를 `FAKE_TODAY` 로 바꿀 수 있음, 조회 300ms)와 가짜 `node-telegram-bot-api`(보내지 않고 `sends.log` 에 한 줄 기록, `FAIL_AT=n` 이면 n번째 전송 실패)를 두었다. 요약은 하지 않았다(OpenRouter 키 없음). 실제 `sent.json`·`sent-count.json`·텔레그램은 쓰지 않았다.
  - 같은 날 서로 다른 날짜 21개를 차례로 실행(각 메시지 1개): 21번 모두 종료 코드 0, 전송 20줄, `sent-count.json` 20. 21번째는 "이미 메시지 20개를 보내 하루 한도 20개에 닿았습니다"로 끝났고 요약 단계 줄이 나오지 않았다. 21번째 공시는 `sent.json` 에 없었다.
  - 이어서 `FAKE_TODAY=20261004` 로 21번째 날짜를 다시 실행: 1개 전송, `{"date":"20261004","count":1}`.
  - 18개 보낸 상태에서 공시 100건(메시지 4개 분량) 한 번 실행: 2개(29건씩)만 가고 "남은 메시지 2개(공시 42건)는 보내지 않습니다", `sent.json` 58건, 센 값 20. 같은 날 다시 실행하면 0개 전송. 다음 날로 실행하면 남은 42건이 메시지 2개로 가서 `sent.json` 100건.
  - 18개 보낸 상태에서 서로 다른 날짜 5개를 동시에 실행, 20번 반복: 20번 중 20번 모두 전송 2줄, `sent.json` 2건, 센 값 20, `sent.lock` 없음.
  - 5개 보낸 상태에서 첫 전송이 실패하게 실행: 종료 코드 1, 센 값 5 그대로, `sent.lock` 없음.
  - `sent-count.json` 을 끊긴 JSON, 빈 파일, `{}`, `count` 가 -1 인 것으로 두고 실행: 네 경우 모두 종료 코드 1, 전송 0.
  - 어제 날짜에 20 이 적힌 `sent-count.json` 으로 실행: 1개 전송, `{"date":"20261003","count":1}`.
- 2026-10-03 진짜로 실행: 실제 `sent.json` 에서 `20261001900418` 을 지우고 실제 `node notify.js 20261001` 을 두 번 실행했다.
  - `sent-count.json` 을 `{"date":"20261003","count":20}` 으로 두고 실행: "새로 보낼 것 1건" 뒤 "하루 한도 20개에 닿았습니다. 보내지 않습니다", 종료 코드 0. 요약 비용 줄이 나오지 않았고, `sent.json` 4건 그대로였다.
  - `sent-count.json` 을 지우고 실행: 에코프로비엠 기업설명회(IR)개최 1건이 메시지 1개로 텔레그램에 실제로 갔다. "메시지 1개로 보냄 (오늘 1/20)", `sent-count.json` 은 `{"date":"20261003","count":1}`. 실행 뒤 `sent.json` 은 처음 5건과 `cmp` 로 같았고 `sent.lock` 은 없었다.
- `git check-ignore -v sent-count.json` 으로 `.gitignore` 5번째 줄에 걸리는 것을 확인했다.
- 확인하지 않은 것: 실제 텔레그램으로 20개를 보내 보는 것, 실제 OpenDART·텔레그램으로 동시에 실행하는 것, 실행 중에 KST 자정이 지나는 경우(잠금을 잡은 때의 날짜로 센다), 다른 컴퓨터나 다른 폴더에서 같은 봇으로 실행하는 경우(따로 센다).
