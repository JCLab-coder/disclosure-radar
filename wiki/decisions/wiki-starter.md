# 위키 방식을 다른 프로젝트에 넣는 starter 폴더를 둔다

- 정한 날: 2026-10-03
- 누가 정함: 항목마다 다르다. 각 항목 끝 괄호에 적었다. 근거는 아래 "근거" 참고.
- 상태: 유지
- 관련: [[index]], [[log]], [[wiki-check-hook]], [[wiki-lint]], [[checker-self-edit]]

## 결정

- 이 저장소의 위키 방식(규칙 파일, 위키 뼈대, 점검 스크립트와 훅, 점검 절차)을 다른 프로젝트에도 그대로 쓸 수 있게 starter 폴더로 뽑는다. 이 프로젝트에만 해당하는 내용은 빼고, 다른 프로젝트에 넣는 순서를 함께 적는다. (사용자)
- 만든 방법 (AI 기본값)
  - 위치는 저장소 맨 위 `starter/`. 넣는 순서는 `starter/README.md`.
  - 규칙 파일은 `starter/rules.md` 하나로 두고, 넣을 때 `CLAUDE.md`·`AGENTS.md` 둘로 복사한다. `starter/CLAUDE.md`·`starter/AGENTS.md` 라는 이름으로 두면 이 저장소에서 그 폴더를 다룰 때 하위 폴더 규칙으로 읽힐 수 있기 때문이다. 원본과 다른 곳은 첫 줄(프로젝트 이름 자리)과 규칙 9·10(공시·접수번호 → 자료·자료 번호, "나중에 공개한다" → "공개할 수 있다") 셋이다.
  - `starter/scripts/`·`starter/.githooks/` 는 원본과 같은 파일이다(실행 권한 포함). 원본에 프로젝트에만 해당하는 내용이 없고, 같으면 `diff -r` 로 맞는지 볼 수 있기 때문이다.
  - 위키 뼈대에 넣은 페이지: 목차, 변경 기록, [[wiki-check-hook]]·[[wiki-lint]]·[[checker-self-edit]] 의 일반판. 공시·텔레그램·Railway 등 이 프로젝트의 결정·자료와 옵시디언 자료는 넣지 않았다. `.env`·`wiki/.obsidian/` 을 커밋하지 않는 것은 README 의 `.gitignore` 단계로 옮겼다.
  - 일반판 페이지의 항목 괄호(사용자 / AI 기본값)는 이 저장소에서 누가 정했는지를 그대로 옮겼다. 넣는 프로젝트에서 어떻게 다루는지는 페이지의 "이 프로젝트에 넣음" 칸에 적게 했다. 이 저장소의 확인 칸 시험 결과와 사용자 말 원문은 옮기지 않고 이 저장소 페이지를 가리키게 했다.
  - 넣을 때 채우는 자리는 `{{…}}` 로 표시하고, 남았는지 `grep -rnE '\{\{[^}]+\}\}' CLAUDE.md AGENTS.md wiki` 로 찾게 했다. 처음에 쓴 `grep -rn '{{'` 는 그 명령을 적은 줄 자신도 찍어서 바꿨다(아래 확인).
  - starter 의 [[wiki-lint]] 일반판은 원본과 두 곳이 다르다. 가벼운 점검에서 점검 기록에 기준이 없으면(넣은 직후) "기준이 없어 전체 기록을 본다"고 알리고 전체 기록을 본다. 원본 명령은 기준이 비면 `..HEAD` 가 되어 아무것도 찍지 않고 통과한 것처럼 보인다. 원본은 기준이 있어 지금은 문제가 없으므로 고치지 않았다. 또 "이 프로젝트에서 대조할 것" 칸을 두어 코드 파일·서버를 프로젝트마다 적게 했다.
  - 결정·자료·교훈 페이지 틀을 `starter/page-templates/` 에 두었다. 넣는 프로젝트에는 복사하지 않는다(위키 안에 두면 틀이 결정 페이지로 점검되기 때문이다).
- 원본의 점검 스크립트·훅·규칙 파일·[[wiki-check-hook]]·[[wiki-lint]] 를 바꾸면 `starter/` 의 같은 파일도 같이 고친다. 맞는지는 [[wiki-lint]] 전체 점검 2단계에서 본다. (AI 기본값)
- `starter/` 는 `wiki/` 밖이라 이 저장소 커밋 전 위키 점검(근거·변경 기록·링크)과 `[점검·규칙 변경]` 표시 대상이 아니다. `starter/scripts/`·`starter/.githooks/` 는 이 저장소에서 돌지 않는 복사본이기 때문이다. 비밀값 점검은 모든 파일을 보므로 `starter/` 도 본다. (AI 기본값)

## 이유

- 사용자가 이 위키 방식을 다른 프로젝트에도 쓰려고 한다. 이 저장소에서 겪은 일(변경 기록 고쳐 쓰기, 점검 장치를 고쳐 통과시키기, 위키에 반영되지 않은 커밋)로 생긴 규칙과 장치를 다시 만들지 않고 옮기려는 것이다.

## 확인

모두 2026-10-03, 이 컴퓨터(Node 25.9.0, git 2.54.0). 다른 컴퓨터 조건이 되도록 `GIT_CONFIG_GLOBAL=/dev/null` 로 전역 git 설정을 끄고 scratchpad 에서 했다. README 의 `sh` 코드 블록 5개를 `awk` 로 꺼내 그대로 돌렸다. README 3단계(자리 채우기)는 사람이 하는 일이라 작은 스크립트로 흉내 냈다(점검 기록 줄만 남기고 채움).

- 커밋 없는 새 저장소(A)와, 커밋 1개와 `.gitignore` 가 있는 저장소(B)에 1~5단계를 돌렸다. 둘 다 4단계 커밋이 종료 코드 0 으로 됐고 메시지 첫 줄에 `[점검·규칙 변경]` 과 바뀐 파일 8개 목록이 붙었다. 훅 실행 권한이 있었다. B 의 `.gitignore` 는 있던 줄 뒤에 두 줄이 더해졌다.
- 5단계 시험: A·B 각각 5개 중 5개가 예상대로였다(변경 기록 지난 줄 고치기, 근거 줄 고치기, 없는 링크, 가짜 `.env` 값이 든 파일 4개는 종료 코드 1, 변경 기록에 새 줄 더하기 1개는 0).
- 이 시험에서 3단계 자리 확인 `grep -rn '{{'` 가 `wiki-lint.md` 의 그 명령 줄 자신도 찍는 것을 찾아 정규식으로 바꿨다. 바꾼 뒤 새 저장소(C, 커밋 1개 있음)에서 다시 돌렸다. 3단계 grep 은 점검 기록 줄 1개만 찍었고, 5단계 5개 중 5개가 예상대로였다.
- C 에서 starter [[wiki-lint]] 의 두 코드 블록을 `awk` 로 꺼내 돌렸다. 가벼운 점검: 기준이 없을 때 안내 문구와 기존 커밋 1개(위키 없는 커밋)가 나왔다. 점검 기록에 4단계 커밋 해시를 채워 커밋하고(자리 grep 은 아무것도 찍지 않음), 코드만 바꾼 커밋을 하나 더한 뒤 돌리니 그 커밋 1개만 나왔다. 링크 점검: 페이지 5개, 없는 링크·이어지지 않은 페이지·나가는 링크 없는 페이지 0개.
- 이 저장소에서 README "원본과 맞추기" 명령: `scripts`·`.githooks` 는 "같음", `diff CLAUDE.md starter/rules.md` 는 1번째 줄과 18·19번째 줄(규칙 9·10)만 달랐다.
- 확인하지 않은 것: 사람이 실제 다른 프로젝트에 README 대로 넣는 것(3단계 손으로 채우기 포함), `CLAUDE.md`·`AGENTS.md` 가 이미 있는 프로젝트에 합치는 것, husky 같은 다른 `core.hooksPath` 가 있는 프로젝트, 전역 훅을 켠 상태에서 starter 를 넣는 것, Windows, Codex 가 starter 규칙을 따르는지.
