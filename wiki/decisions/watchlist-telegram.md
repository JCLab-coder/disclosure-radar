## 결정

- 관심 종목에 공시가 올라오면 `notify.js` 가 텔레그램으로 보낸다. (사용자)
- ~~공시 한 건에 메시지 하나씩 보낸다. (AI 기본값)~~ → 2026-10-03 바뀜: 한 번 실행에 메시지 하나로 모아 보낸다. (사용자)
  - 텔레그램 메시지 한도(4096자)를 넘을 때만 공시 단위로 나눠 여러 개로 보낸다. 나눈 메시지 머리말에는 "(이어서)"를 붙인다. (AI 기본값)
  - 관심 종목 공시가 0건이면 아무것도 보내지 않는다. (AI 기본값. 이전 동작 그대로다.)
- 그날(기본: 오늘, KST) 공시를 본다. 사용법은 `node notify.js [YYYYMMDD]`. (확인 안 됨)
- 관심 종목은 삼성전자(005930), 카카오(035720), 에코프로비엠(247540) 세 개로 시작한다. `notify.js` 의 `WATCHLIST` 에 있다. (사용자)
- 관심 종목은 회사 이름이 아니라 종목코드(`stock_code`)로 맞춘다. (AI 기본값)
- 중복 처리는 아직 하지 않는다. 한 번 실행하면 그날 공시를 한 번 보낸다. 다시 실행하면 같은 공시를 또 보낸다. 중복 처리는 나중에 하기로 했다. (사용자)
- 의존성은 추가하지 않는다. 텔레그램 Bot API 는 Node 내장 `fetch` 로 부른다. (사용자)
- 텔레그램 비밀값은 `.env` 의 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` 에 둔다. (사용자)
- 공시 조회 코드는 `dart.js` 로 옮겨 `index.js` 와 `notify.js` 가 같이 쓴다. (사용자. 처음에는 AI 기본값이었다.)
  - 2026-10-03 덧붙임: 이 분리는 처음엔 이전 세션이 고른 것이었다. 이후 사용자가 이유를 듣고 유지하기로 확정했다. [[file-structure]] 참고.

## 이유

- 종목코드로 맞추는 이유: 이름에 "카카오"가 들어가면 카카오뱅크·카카오페이·카카오페이증권이, "삼성전자"가 들어가면 삼성전자서비스씨에스가 같이 걸린다. 2026-09-29 ~ 10-02 공시에서 실제로 확인했다.
- 중복 처리·의존성은 사용자가 지금은 하지 말라고 했다.

## 확인

- 2026-10-03 모아 보내기로 바꾼 뒤 `node --env-file=.env notify.js 20261001` 로 다시 보냈다. 관심 종목 공시 5건이 메시지 1개로 갔다. 같은 공시 60건을 넣은 가짜 데이터로는 4031자·1367자 두 메시지로 나뉘고 60건이 모두 들어가는 것을 확인했다(실제 전송은 하지 않음).
- 2026-10-03 은 토요일·개천절이라 공시가 0건이었고, 아무것도 보내지 않았다.
- `node notify.js 20261001` 로 관심 종목 공시 5건(에코프로비엠 2, 삼성전자 2, 카카오 1)을 실제로 보냈고, 텔레그램 API 가 모두 `ok` 로 응답했다. 같은 날 카카오뱅크 등은 섞이지 않았다.
