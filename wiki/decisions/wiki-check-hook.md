# 커밋 전에 위키와 비밀값을 점검하는 git 훅을 둔다

- 정한 날: 2026-10-03
- 누가 정함: 항목마다 다르다. 각 항목 끝 괄호에 적었다. 근거는 아래 "근거" 참고.
- 상태: 유지
- 관련: [[index]], [[log]], [[env-not-committed]]

## 결정

- [[log]] 의 지난 기록은 고쳐 쓰지 않는다. 새 기록을 맨 위에 더한다. (사용자)
- 규칙만으로는 빈틈이 생기므로 커밋 전에 위키를 점검하는 스크립트를 git 훅으로 건다. 문제가 있으면 커밋이 안 된다. 훅 파일도 저장소에 넣는다. (사용자)
- 점검하는 것은 세 가지다. (사용자)
  - `wiki/log.md` 의 지난 줄이 바뀌거나 지워졌는지
  - 결정 페이지(`wiki/decisions/*.md`)의 "## 근거" 칸 줄이 지워졌는지
  - `[[링크]]` 가 없는 페이지를 가리키는지
- 점검 방법 (AI 기본값)
  - 스크립트는 `scripts/check-wiki.mjs`(Node, 의존성 없음). 스테이지된 내용을 마지막 커밋(HEAD)과 비교한다. 작업 트리는 보지 않는다.
  - 변경 기록: HEAD 의 빈 줄이 아닌 줄이 순서대로 모두 그대로 남아 있어야 한다. 새 줄은 어디에 더해도 된다. 머리말 줄을 고쳐도 막힌다.
  - 근거 칸: HEAD 의 근거 줄이 같은 페이지 근거 칸에 글자 하나 다르지 않게 있어야 한다. 줄을 고치는 것도 지운 것으로 본다(원문을 줄이는 것을 막으려는 것이다). 근거를 더할 때는 새 줄로 더한다.
  - 결정 페이지 파일을 지우는 것도 막는다. 결정을 뒤집을 때는 페이지를 지우지 않는다는 [[index]] 쓰는 규칙에 맞춘 것이다.
  - 링크: `wiki/` 안의 `.md`(`wiki/.obsidian/` 제외)에서 `[[이름]]` 을 찾아, 같은 이름의 `.md` 가 `wiki/` 아래 어디에든 있으면 통과. `` `…` `` 코드 안과 큰따옴표 `"…"` 안은 보지 않는다. 근거의 대화 원문은 큰따옴표 안에 그대로 적는데, 그 안의 `[[…]]` 는 링크가 아니라 사용자가 한 말이기 때문이다(이 페이지 근거의 훅 요청 원문). (2026-10-03 위키 점검 때 덧붙임: "`wiki/` 아래 어디에든 있으면"은 정확히는 git 에 올라간 파일(`git ls-files wiki/`)이다(`scripts/check-wiki.mjs` 75번째 줄). 커밋하지 않은 새 페이지를 가리키는 링크는 그 페이지를 `git add` 하기 전까지 없는 페이지로 본다. [[obsidian-wiki]] 에 적은 것과 같다.)
- 훅은 `.githooks/pre-commit` 이고 `git config core.hooksPath .githooks` 로 켠다. (AI 기본값)
  - 이 컴퓨터는 전역 설정(`~/.gitconfig`)에 `core.hooksPath` 가 있고, 거기 `pre-commit` 은 비밀키가 커밋에 섞이는 것을 막는다. 저장소에서 `core.hooksPath` 를 바꾸면 전역 훅이 돌지 않는다. 그래서 `.githooks/pre-commit` 은 전역 `pre-commit` 이 있으면 먼저 부르고, 그다음 위키 점검을 한다. (AI 기본값) (2026-10-03 위키 점검 때 덧붙임: 전역 훅을 먼저 부르는 것은 그대로다. 그 뒤 순서는 이후 두 번 바뀌었다. 지금 순서는 아래 "마지막 커밋의 점검 스크립트를 돌리고…" 칸의 "훅 순서"를 본다.)
  - `core.hooksPath` 는 `.git/config` 에 들어가 저장소와 함께 옮겨지지 않는다. 새로 받은 저장소에서는 위 명령을 한 번 돌려야 켜진다. `package.json` 의 `prepare` 로 자동으로 켜는 것은 하지 않았다. Railway 빌드의 `npm install` 에서도 돌아 git 이 없는 곳에서 실패할 수 있기 때문이다. (AI 기본값)
- `git commit --no-verify` 로 건너뛸 수 있다. 사용자가 시키지 않으면 쓰지 않는다. (AI 기본값)

### 비밀값 점검 (2026-10-03 더함)

- 위키나 커밋에 `.env` 의 실제 값이 들어가면 이 저장소 스크립트가 커밋을 막는다. 가짜 키를 막은 것은 이 컴퓨터에만 있는 전역 훅이라, 이 저장소를 받은 다른 컴퓨터에서는 막히지 않기 때문이다. (사용자)
- 값은 화면에 찍지 않는다. 키 이름과 파일·줄 번호만 알린다. (사용자)
- 방법 (AI 기본값)
  - 스크립트는 `scripts/check-secrets.mjs`. 저장소 폴더의 `.env` 를 `node:util` 의 `parseEnv` 로 읽고, 스테이지된 변경에서 더해지는 줄(위키만이 아니라 모든 파일, `git add -f .env` 포함)에 그 값이 그대로 들어 있는지 본다.
  - 커밋 메시지도 본다. 그래서 `.githooks/commit-msg` 를 더했다. pre-commit 처럼 전역 `commit-msg` 가 있으면 먼저 부른다.
  - `.githooks/pre-commit` 은 전역 훅 → 비밀값 점검 → 위키 점검 차례로 돈다.
  - 6자보다 짧은 값은 보지 않는다. 흔한 글자와 겹치기 때문이다. 2026-10-03 이 컴퓨터 `.env` 의 값 네 개는 모두 10자 이상이다.
  - `.env` 가 없는 컴퓨터에서는 비교할 값이 없으므로 점검을 건너뛰고 "`.env` 가 없어 비밀값 점검을 건너뜁니다"라고 알린다.
- 이 점검이 막지 못하는 것 (AI 기본값, 알고 둔 한계)
  - 값을 바꿔 적은 것(나눠 적기, base64 등 인코딩, 일부만 적기).
  - `.env` 에 없고 서버 변수에만 있는 값. 2026-10-03 에는 서버의 키 네 개가 로컬 `.env` 와 같았다([[railway-deploy]] 확인 칸). 이후 한쪽만 바꾸면 다를 수 있다.
  - 이미 커밋된 기록. 새 커밋만 본다.
  - 훅을 켜지 않은 컴퓨터(`core.hooksPath` 를 설정하지 않은 곳), `--no-verify`.

### 마지막 커밋의 점검 스크립트를 돌리고, 점검·규칙 변경을 표시한다 (2026-10-03 더함)

위에서 "`.githooks/pre-commit` 은 전역 훅 → 비밀값 점검 → 위키 점검 차례로 돈다"고 적은 것은 이 칸으로 바뀌었다. 바뀐 이유는 [[checker-self-edit]].

- 훅은 작업 트리의 점검 스크립트가 아니라 마지막 커밋(HEAD)에 있는 점검 스크립트를 돌린다. 커밋 안에서 점검 스크립트를 고쳐도, 그 커밋은 고치기 전 스크립트로 점검된다. (사용자)
- 점검 장치나 규칙 파일이 바뀌는 커밋은 따로 표시해 사람이 알아보게 한다. (사용자)
- 방법 (AI 기본값)
  - 훅은 `git show HEAD:scripts/<이름>` 을 임시 폴더에 꺼내 `node` 로 돌리고 끝나면 지운다. `check-secrets.mjs`·`check-wiki.mjs`·`check-guard.mjs` 셋 모두 이렇게 돈다.
  - HEAD 에 그 스크립트가 없으면(첫 커밋, 새로 더한 스크립트) 스테이지된 것을 돌리고 "마지막 커밋에 없어 스테이지된 것을 돌립니다"라고 알린다. HEAD 에도 스테이지에도 없으면 커밋을 막는다.
  - 표시는 새 스크립트 `scripts/check-guard.mjs` 가 한다. 막지는 않는다. pre-commit 에서 바뀌는 파일을 화면에 알리고, commit-msg 에서 커밋 메시지 첫 줄 앞에 `[점검·규칙 변경]` 을 붙이고 첫 줄 아래에 "바뀐 점검 장치·규칙 파일: …" 줄을 넣는다. 그래서 `git log --oneline` 에서 바로 보인다.
  - 표시하는 파일: `.githooks/` 아래 전부, `scripts/` 아래 전부, `CLAUDE.md`, `AGENTS.md`, 이 페이지(`wiki/decisions/wiki-check-hook.md`). [[index]] 의 쓰는 규칙은 넣지 않았다. 거의 모든 커밋에서 목차를 고치므로 표시가 늘 붙어 뜻이 없어지기 때문이다.
  - 표시하는 파일 목록도 `check-guard.mjs` 안에 있어 HEAD 의 것이 쓰인다. 목록에서 파일을 빼는 커밋은 뺀 전 목록으로 표시된다.
  - 훅 순서: pre-commit 은 전역 훅 → 표시 알림 → 비밀값 점검 → 위키 점검. commit-msg 는 전역 훅 → 메시지 비밀값 점검 → 표시 붙이기.
- 지난 커밋 중 점검 장치·규칙을 바꾼 것은 훅과 상관없이 git 기록으로 찾는다. 메시지 표시는 훅이 붙이는 것이라 훅을 끄거나 고치면 빠질 수 있지만, 이 명령은 그렇지 않다. (AI 기본값)
  - `git log --oneline -- .githooks scripts CLAUDE.md AGENTS.md wiki/decisions/wiki-check-hook.md`
- 이 방법이 막지 못하는 것 (AI 기본값, 알고 둔 한계)
  - 훅 파일(`.githooks/*`) 자체는 git 이 작업 트리의 것을 돌린다. 작업 트리의 pre-commit 을 고치면 그 커밋부터 점검이 빠진다. 다만 commit-msg 를 그대로 두면 표시는 붙는다(아래 확인 7번). 둘 다 고치면 표시도 빠지므로, 그때는 위 `git log` 명령으로 찾는다.
  - 점검 스크립트를 고친 커밋을 먼저 따로 커밋하면, 그다음 커밋부터는 고친 스크립트가 쓰인다(아래 확인 6번). 이것은 막지 않고, 고친 커밋에 표시가 붙어 사람이 보게 하는 것으로 둔다.
  - `--no-verify`, 훅을 켜지 않은 컴퓨터.
- 장치가 막지 못하는 빈틈은 규칙으로 막는다. `CLAUDE.md`·`AGENTS.md` 규칙 11: 점검에 막히면 통과시키려고 규칙 파일·점검 스크립트·훅·위키의 결정을 고치지 않고(`--no-verify` 도 쓰지 않고) 사용자에게 묻는다. 규칙이나 장치를 바꿔야 하면 먼저 묻고, 그 변경만 따로 커밋한다. AI 가 제안한 것을 사용자가 듣고 넣자고 확정했다. (사용자, 2026-10-03 더함)

## 이유

- 2026-10-03 위키를 줄여 달라는 요청에 AI 가 [[log]] 의 지난 기록을 한 줄씩으로 고쳐 썼다. 그러면서 "다른 컴퓨터에서 실제로 돌려 보지는 않음" 같은 단서가 빠졌다. 그때는 변경 기록에 관한 규칙이 없었다. 사용자가 되돌리게 했다.

### 비밀값 점검 확인 (2026-10-03)

scratchpad 에 이 저장소를 `git clone` 하고 작업 중인 스크립트·훅과 이 컴퓨터의 `.env` 를 복사했다. `GIT_CONFIG_GLOBAL=/dev/null` 로 전역 설정을 끄고(전역 `core.hooksPath` 가 빈 값임을 출력으로 확인) 돌렸다. 전역 비밀키 훅 없이 이 저장소 스크립트만으로 막히는지 보려는 것이고, 다른 컴퓨터의 조건이다. 값은 작은 스크립트가 `.env` 에서 읽어 파일에 바로 넣었고 화면에 찍지 않았다.

- 1차 시험에서 두 가지가 드러났다. `commit-msg` 에 실행 권한이 없어 git 이 무시했다(`chmod +x` 로 고침). 시험 스크립트가 5번 뒤 `git reset --hard` 로 복제본의 `.env` 를 지워 6번부터는 `.env` 없이 돌았다(시험 쪽 실수, 실제 저장소 `.env` 는 그대로인 것을 확인). 고쳐서 복제본을 새로 만들어 다시 했다. 아래는 2차 결과다.
- 막혀야 하는 6개 중 6개가 막혔다. 출력에는 키 이름과 파일·줄 번호만 나왔다.
  1. 위키 자료 페이지 끝에 `OPENROUTER_API_KEY` 값 한 줄
  2. 결정 페이지에 `OPENDART_API_KEY` 값(줄 중간, 앞뒤에 다른 글)
  3. `notify.js` 에 `TELEGRAM_BOT_TOKEN` 값
  4. 새 파일에 `TELEGRAM_CHAT_ID` 값
  5. `git add -f .env`: 네 키 모두 짚음
  6. 커밋 메시지에 `OPENDART_API_KEY` 값: pre-commit 은 통과하고 commit-msg 가 막음
- 통과해야 하는 2개 중 2개가 커밋됐다: 키 이름과 자리 표시자(`OPENDART_API_KEY=<값>`)만 적은 줄, `.env` 를 지운 상태의 커밋(건너뛴다는 문구가 나옴).
