# 한 번 보낸 공시는 다시 보내지 않는다

- 정한 날: 2026-10-03
- 누가 정함: 항목마다 다르다. 각 항목 끝 괄호에 적었다. 근거는 아래 "근거" 참고.
- 상태: 유지
- 관련: [[index]], [[log]], [[watchlist-telegram]], [[disclosure-summary]], [[env-not-committed]], [[concurrent-runs]], [[daily-message-limit]], [[railway-deploy]]

## 결정

- `notify.js` 는 한 번 텔레그램으로 보낸 공시를 다시 보내지 않는다. 같은 날 여러 번 실행해도 새 공시만 간다. (사용자)
  - 2026-10-03 덧붙임: 처음 만든 코드는 차례로 실행할 때만 이렇게 됐다. 동시에 두 번 실행하면 같은 공시가 두 번 갔다(사용자가 발견). 아래 잠금 항목을 더해 고쳤다. [[concurrent-runs]] 참고.
- 공시는 접수번호(`rcept_no`)로 가린다. 접수번호는 공시마다 하나다. (AI 기본값)
- 보낸 접수번호는 프로젝트 폴더의 `sent.json`(JSON 배열)에 남긴다. 파일이 없으면 아무것도 안 보낸 것으로 본다. (AI 기본값)
- `sent.json` 은 실행하면서 생기는 상태 파일이라 `.gitignore` 에 넣어 커밋하지 않는다. (AI 기본값)
- 메시지 하나가 전송에 성공할 때마다 그 메시지에 들어간 공시를 `sent.json` 에 남긴다. 4096자를 넘어 메시지가 나뉘었는데 뒤 메시지가 실패하면, 이미 간 앞 메시지의 공시는 다음 실행에 다시 보내지 않고 못 간 공시만 보낸다. (AI 기본값)
- 이미 보낸 공시는 요약도 하지 않는다. 새로 보낼 공시만 원문 조회·요약을 한다. 새로 보낼 공시가 0건이면 아무것도 보내지 않는다. (AI 기본값)
- 메시지 머리말의 건수는 이번에 새로 보내는 건수다. (AI 기본값)
- `sent.json` 의 오래된 접수번호는 지우지 않는다. (AI 기본값)
- 2026-10-03 더함: `sent.json` 읽기부터 마지막 기록까지를 잠금 파일 `sent.lock` 으로 감싼다. `sent.lock` 은 `wx`(이미 있으면 실패)로 만들고 안에 잡은 실행의 pid 를 적는다. 끝나면(전송 실패로 끝날 때도) 지운다. (AI 기본값)
  - 잠금이 이미 있으면 뒤 실행은 0.5초마다 다시 보며 기다렸다가, 잡은 뒤 `sent.json` 을 다시 읽는다. 그래서 앞 실행이 보낸 공시는 빠진다. 건너뛰지 않고 기다리는 이유는, 다른 날짜를 동시에 실행했을 때 뒤 실행의 공시가 빠지지 않게 하려는 것이다. (AI 기본값)
  - 10분을 기다려도 못 잡으면 보내지 않고 오류로 끝난다(종료 코드 1). (AI 기본값)
  - 잠금에 적힌 pid 의 프로세스가 없으면(강제 종료 등으로 남은 잠금) 지우고 다시 잡는다. (AI 기본값)
  - 공시 목록 조회(OpenDART)는 잠금 밖에서 한다. 요약(OpenRouter)과 전송은 잠금 안에서 한다. 요약할 공시는 `sent.json` 을 읽어야 정해지기 때문이다. (AI 기본값)
  - `sent.lock` 도 `.gitignore` 에 넣었다. (AI 기본값)
- `sent.json` 이 깨져 읽을 수 없으면 요약·전송 없이 오류로 끝난다(종료 코드 1). 빈 목록으로 보고 계속하면 그날 공시가 모두 다시 가기 때문이다. 사람이 고치거나 지울 때까지 알림이 멈춘다. (AI 기본값)

- 2026-10-03 덧붙임: 서버(Railway)에서는 `sent.json`·`sent.lock` 을 볼륨 `/data` 에 둔다. `STATE_DIR` 변수가 있으면 그 폴더, 없으면 전처럼 프로젝트 폴더다. `sent.lock` 에 적힌 pid 가 자기 pid 와 같으면 남은 잠금으로 보고 치운다(컨테이너에서 pid 가 겹칠 수 있다). 서버와 로컬은 `sent.json` 을 따로 가진다. [[railway-deploy]] 참고. (AI 기본값)

## 이유

- 접수번호로 가리는 이유: 같은 회사가 같은 날 같은 이름의 보고서를 여러 건 낼 수 있다(2026-10-01 삼성전자 "임원ㆍ주요주주특정증권등소유상황보고서" 2건). 회사·보고서 이름으로는 가릴 수 없다.
- 메시지마다 남기는 이유: 다 보낸 뒤 한꺼번에 남기면 중간에 실패했을 때 이미 간 공시가 다음 실행에 또 간다.
- 오래된 접수번호를 지우지 않는 이유: 관심 종목 공시는 하루 몇 건이라 파일이 거의 커지지 않는다. 지우는 기준을 따로 두면 지난 날짜를 다시 실행할 때 또 갈 수 있다.

## 확인

- 2026-10-03 `sent.json` 이 없는 상태에서 `node notify.js 20261001` 을 두 번 실제로 실행했다.
  - 1회차: "관심 종목 공시 5건 (전체 648건), 이미 보낸 것 0건 빼고 새로 보낼 것 5건", "메시지 1개로 보냄". 텔레그램으로 실제로 갔다. `sent.json` 에 접수번호 5개(`20261001000203`, `20261001000251`, `20261001800065`, `20261001900314`, `20261001900418`)가 남았다.
  - 2회차: "관심 종목 공시 5건 (전체 648건), 이미 보낸 것 5건 빼고 새로 보낼 것 0건". 요약도 전송도 하지 않고 종료 코드 0 으로 끝났다.
- `git check-ignore -v sent.json` 으로 `.gitignore` 3번째 줄에 걸리는 것을 확인했다.
- 2026-10-03 일부만 새 공시인 경우(진짜로 실행): 실제 `sent.json` 에서 `20261001900418` 하나를 지우고 `node notify.js 20261001` 을 실행했다. 실제 OpenDART·OpenRouter·텔레그램을 썼다. "이미 보낸 것 4건 빼고 새로 보낼 것 1건", 그 1건(에코프로비엠 기업설명회(IR)개최)만 메시지 1개로 실제로 갔다. 요약 비용은 약 $0.00009 로 1건분이었다. 실행 뒤 `sent.json` 은 처음 5건과 `cmp` 로 같았다.
- 2026-10-03 메시지가 나뉘어 뒤 메시지가 실패하는 경우(가짜로 실행): 텔레그램이 일부러 실패하게 만들 수 없어 가짜로 했다. `notify.js` 를 고치지 않고 scratchpad 폴더에 복사했다(`cmp` 로 원본과 같음을 확인). 같은 폴더에 가짜 `dart.js`(관심 종목 공시 60건, 가짜 접수번호 `FAKE0000`~`FAKE0059`)와 가짜 `node-telegram-bot-api`(보내지 않고 기록만 하며, `FAIL_AT=2` 이면 2번째 `sendMessage` 에서 실패)를 두고 실행했다. 요약은 하지 않았다(OpenRouter 키 없음). 실제 `sent.json` 은 건드리지 않았다.
  - 2번째 메시지 실패: 1번째 메시지(4026자, `FAKE0000`~`FAKE0039` 40건)만 가고 종료 코드 1. `sent.json` 에 40건이 남았다.
  - 다시 실행(실패 없음): "이미 보낸 것 40건 빼고 새로 보낼 것 20건", 메시지 1개(2026자, `FAKE0040`~`FAKE0059` 20건)가 갔다. 머리말은 "관심 종목 공시 20건". `sent.json` 60건.
  - 한 번 더 실행: 새로 보낼 것 0건, 전송 0번.
- 2026-10-03 `sent.json` 이 깨진 경우(진짜로 실행): 실제 `sent.json` 을 세 가지로 깨뜨리고 실제 `node notify.js 20261001` 을 실행했다. 중간에 끊긴 JSON(`["20261001000203", "2026100`), 빈 파일, `{}` 세 경우 모두 "sent.json 을 읽지 못했습니다: …"로 종료 코드 1 이었다. 요약·전송 줄은 나오지 않았고, `sent.json` 내용도 바뀌지 않았다. 시험 뒤 원래 5건으로 되돌리고 `cmp` 로 확인했다.
- `sent.json` 을 쓰는 도중에 프로그램이 죽는 경우(파일이 반쯤 써지는 경우)는 확인하지 않았다.
- 위 확인은 모두 차례로 실행한 것이다. 동시 실행은 처음에 시험하지 않았고, 사용자가 동시에 두 번 실행해 같은 공시가 텔레그램으로 두 번 간 것을 발견했다. [[concurrent-runs]] 참고.
- 2026-10-03 동시 실행(가짜로 실행): scratchpad 폴더에 `notify.js` 를 복사하고(`cmp` 로 원본과 같음 확인), 가짜 `dart.js`(관심 종목 공시 5건 `FAKE0000`~`FAKE0004`, 조회에 300ms 걸리게 함)와 가짜 `node-telegram-bot-api`(보내지 않고 200ms 뒤 pid 와 접수번호를 `sends.log` 에 한 줄 기록)를 두었다. 매번 `sent.json` 을 4건(`FAKE0004` 뺌)으로 두고 시작했다. 요약은 하지 않았다(OpenRouter 키 없음). 실제 `sent.json`·텔레그램은 쓰지 않았다.
  - 고치기 전 코드, 동시에 2개: 사용자가 본 것과 같았다. 두 실행 모두 "새로 보낼 것 1건", "메시지 1개로 보냄", `sends.log` 에 `FAKE0004` 전송 2줄, `sent.json` 5건.
  - 고친 코드, 동시에 2개: 한 실행은 1건을 보냈고, 다른 실행은 "다른 실행(pid …)이 끝나기를 기다립니다" 뒤 "이미 보낸 것 5건 빼고 새로 보낼 것 0건". 전송 1줄, `sent.json` 5건, 끝난 뒤 `sent.lock` 없음.
  - 고친 코드, 동시에 5개를 20번 반복: 20번 중 20번 모두 전송 1줄, `sent.json` 5건, `sent.lock` 없음.
  - 죽은 pid 가 적힌 `sent.lock` 을 미리 두고 실행: "이전 실행(pid …)이 남긴 sent.lock 을 지웁니다" 뒤 1건 전송, 종료 코드 0, `sent.lock` 없음.
  - 살아 있는 프로세스(`sleep 30`) pid 를 적은 `sent.lock` 을 두고, 대기 한도만 1초로 바꾼 복사본으로 실행: 기다리다 종료 코드 1, 남의 `sent.lock` 은 지우지 않았다. 10분 한도 자체는 기다려 보지 않았다.
  - 가짜 전송이 실패하게 하고 실행: 종료 코드 1, `sent.lock` 없음(풀림), `sent.json` 4건 그대로.
- 실제 OpenDART·OpenRouter·텔레그램으로 동시에 실행해 보는 것은 하지 않았다.
- 확인하지 않은 경우: 남은 잠금의 pid 를 다른 프로세스가 다시 쓰고 있으면 살아 있는 것으로 보고 10분 기다린 뒤 실패한다. 두 실행이 동시에 같은 남은 잠금을 치우려 하면 둘 다 잠금을 잡을 수 있는 짧은 틈이 있다. 둘 다 시험하지 않았다. 다른 컴퓨터나 다른 폴더에서 같은 봇으로 실행하는 경우는 이 잠금으로 막히지 않는다.

## 근거

- 2026-10-03 대화: "같은 날 두 번 실행하면 같은 공시가 또 와. 한 번 보낸 공시는 다시 보내지 않게 해 줘. 만들고 실제로 두 번 실행해서 두 번째에는 안 가는 것까지 확인해 줘."
- 접수번호·`sent.json`·`.gitignore`·메시지마다 남기기·요약 생략·오래된 번호 유지·깨진 `sent.json` 이면 멈추기는 사용자가 말하지 않았다. 구현하면서 AI 가 고른 것이다.
- 동시 실행 잠금: 2026-10-03 대화: "sent.json 에서 한 건을 지우고 터미널에서 node notify.js 20261001 을 동시에 두 번 돌려 봤더니 같은 공시가 텔레그램으로 두 번 왔어. 두 실행 모두 새로 보낼 것 1건, 메시지 1개로 보냄이라고 나왔고 sent.json 은 5건으로 멀쩡해. 원인을 찾아서 고쳐 주고, 이번 일을 다음 세션이 같은 실수를 하지 않게 위키에 교훈으로 남겨 줘." 고치라는 것은 사용자, 잠금 파일·기다리기·10분·남은 잠금 치우기 등 방법은 AI 가 고른 것이다.
- 추가 시험: 2026-10-03 대화: "확인하지 않았다고 한 세 가지를 실제로 시험해 줘. 텔레그램으로 실제로 보내지 않아도 되는 건 가짜로 해도 되는데, 무엇을 진짜로 하고 무엇을 가짜로 했는지 구분해서 알려 줘."
